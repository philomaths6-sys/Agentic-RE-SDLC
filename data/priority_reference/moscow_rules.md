## MoSCoW Prioritisation Rules

- **Must Have**: Regulatory or compliance‑linked requirements, core transactional functionality, or any feature that is non‑negotiable. These items must be delivered in the current development cycle.
- **Should Have**: Important features that add significant value but have viable work‑arounds or alternative solutions. They should be implemented if resources allow.
- **Could Have**: Low‑impact or nice‑to‑have features that can be deferred without harming the product. Inclusion is optional and based on capacity.
- **Won't Have this cycle**: Items explicitly deferred for a future cycle. They are documented for transparency but are not scheduled for implementation now.
